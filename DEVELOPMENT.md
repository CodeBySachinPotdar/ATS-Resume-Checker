# DEVELOPMENT.md — Developer Handbook & Operations Guide

Welcome to the **ResumeMatch AI** development guide. This document provides step-by-step instructions for running, debugging, testing, and extending the codebase.

---

## 1. Prerequisites

Ensure the following tools are installed:
- **Java**: Version 21 or higher (OpenJDK, Temurin, or Oracle JDK)
- **Apache Maven**: Version 3.9+
- **Node.js**: Version 20+ (LTS)
- **npm**: Version 10+
- **Docker & Docker Compose**: (Optional for full microservice stack; embedded modes exist for single-laptop development)

Verify your environment:
```bash
java -version
mvn -version
node -v
npm -v
docker --version
```

---

## 2. Environment Variables

All variables have development defaults configured in `application.yml` and can be overridden via environment variables or `.env` files:

| Variable | Default (Dev) | Docker (Prod) | Description |
|---|---|---|---|
| `SPRING_DATASOURCE_URL` | `jdbc:h2:mem:resumematchdb` | `jdbc:postgresql://postgres:5432/resumematchdb` | Database connection URL |
| `SPRING_DATASOURCE_USERNAME` | `sa` | `resumematch` | Database username |
| `SPRING_DATASOURCE_PASSWORD` | *(empty)* | `secretpassword` | Database password |
| `KAFKA_BOOTSTRAP_SERVERS` | `localhost:9092` | `kafka:9092` | Kafka broker endpoints |
| `KAFKA_ENABLED` | `false` | `true` | Toggles Kafka event pipeline vs in-process worker |
| `REDIS_HOST` | `localhost` | `redis` | Redis cache hostname |
| `REDIS_ENABLED` | `false` | `true` | Toggles Redis caching |
| `AI_PROVIDER` | `mock` | `mock` (or `openai`, `gemini`) | Active AI Provider |
| `OPENAI_API_KEY` | *(empty)* | `sk-...` | OpenAI API key (if using OpenAIProvider) |
| `JWT_SECRET` | `404E6352...` | *(generate unique secret in prod)* | HMAC-SHA256 signature key |

## 3. Running the Application

### Option A: Complete Docker Compose Stack
Runs PostgreSQL, Redis, Apache Kafka (KRaft), Backend, and Frontend SPA:

```bash
# From repository root:
docker compose up --build
```

- **Frontend Application**: [http://localhost:3000](http://localhost:3000)
- **Backend REST API**: [http://localhost:8080](http://localhost:8080)
- **Swagger UI**: [http://localhost:8080/swagger-ui.html](http://localhost:8080/swagger-ui.html)

To tear down:
```bash
docker compose down -v
```

---

### Option B: Local Standalone Development (Zero Docker Required)

In standalone mode, Spring Boot uses embedded H2 and in-process `@Async` task queues.

#### Step 1: Start Backend
```bash
cd backend
mvn clean spring-boot:run
```
*The backend starts on port 8080.*

#### Step 2: Start Frontend
In a new terminal:
```bash
cd frontend
npm install
npm run dev
```
*The Vite dev server starts on [http://localhost:5173](http://localhost:5173) with automatic proxying to localhost:8080.*

## 5. How to Add a New Feature

### Adding a New Domain Service
1. Create entity in `com.resumematch.entity`.
2. Create repository interface extending `JpaRepository` in `com.resumematch.repository`.
3. Create service class in `com.resumematch.service` annotated with `@Service` and `@Transactional`.
4. Create controller in `com.resumematch.controller` annotated with `@RestController`, `@RequestMapping`, and `@Tag`.
5. Write JUnit 5 unit tests in `src/test/java/com/resumematch/`.

### Adding a New Kafka Event
1. Define event POJO in `com.resumematch.kafka`:
   ```java
   public class MyNewEvent implements Serializable { ... }
   ```
2. Inject `KafkaTemplate<String, Object>` in your producer service.
3. Publish to topic:
   ```java
   kafkaTemplate.send("my-new-topic", String.valueOf(key), event);
   ```
4. Create a listener in your consumer:
   ```java
   @KafkaListener(topics = "my-new-topic", groupId = "resumematch-workers")
   public void handleEvent(MyNewEvent event) { ... }
   ```
5. Document the new topic and payload in [EVENT-CATALOG.md](EVENT-CATALOG.md).

### Connecting to an External OpenAI Account
Set environment variables before starting the backend:
```bash
export AI_PROVIDER=openai
export OPENAI_API_KEY=sk-your-actual-api-key
export OPENAI_MODEL=gpt-4o-mini
```
Or set them in `application.yml`. If the API key is not configured or an error occurs, the system automatically falls back to `MockAIProvider` so your application never crashes.

## 6. Debugging Tips

- **Check API Contracts**: Open [http://localhost:8080/swagger-ui.html](http://localhost:8080/swagger-ui.html) to test endpoints interactively.
- **Inspect SQL Queries**: Set `spring.jpa.show-sql: true` in `application.yml` to view queries generated by Hibernate.
- **H2 Console**: Accessible at `http://localhost:8080/h2-console` (JDBC URL: `jdbc:h2:mem:resumematchdb`, username: `sa`, password: blank).
- **Frontend State**: Check `localStorage.getItem('last_analysis')` in browser DevTools to inspect cached analysis payloads.
